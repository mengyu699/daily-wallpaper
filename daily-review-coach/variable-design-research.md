# 扣子平台变量设计深度调研报告

## 一、关于开场白动态配置

### 调研结果
**扣子的标准开场白功能不支持直接根据时间动态变化**

### 解决方案

#### 方案1：通过提示词实现（推荐）
```markdown
# 在提示词中添加
根据当前时间{{current_time}}，使用不同的问候语：
- 6:00-11:00：🌅 早安！新的一天开始了...
- 11:00-13:00：☀️ 中午好！工作进展如何...
- 13:00-18:00：🌤 下午好！继续加油...
- 18:00-23:00：🌙 晚上好！准备复盘了吗...
- 23:00-6:00：🌃 夜深了，注意休息...
```

#### 方案2：通过工作流实现
创建一个初始化工作流：
1. 获取系统时间
2. 条件判断节点（if-else）
3. 根据时间段返回不同问候语
4. 设置到应用变量greeting_message

#### 方案3：固定开场白+动态首句
开场白保持固定，但在Bot回复的第一句话中加入时间判断。

## 二、变量设计深度分析

### 三种变量的本质区别

| 变量类型 | 生命周期 | 数据类型 | 跨会话 | 适用场景 |
|---------|---------|---------|--------|---------|
| **系统变量** | 会话期间 | 多种 | ❌ | 获取用户ID、时间等 |
| **应用变量** | 工作流执行期间 | 多种 | ❌ | 临时计算、状态标记 |
| **用户变量** | 永久 | 仅String | ✅ | 用户偏好、个性化设置 |

### 关键发现

1. **变量不能解决数据存储问题**
   - 应用变量每次重置，不适合存储规划
   - 用户变量虽然跨会话，但只支持String
   - 无法存储结构化的规划数据

2. **变量的真正用途**
   - 个性化设置（称呼、偏好）
   - 临时状态标记
   - 系统信息获取

## 三、针对复盘教练的最优变量设计

### 必要的系统变量（开启）
```yaml
sys_uuid          # 用户唯一标识（关键！数据库查询依赖此ID）
current_date      # 当前日期（YYYY-MM-DD格式）
current_time      # 当前时间（HH:mm格式）
```

### 用户变量（跨会话保存）
```yaml
user_name:
  类型: String
  默认值: "朋友"
  用途: 存储用户昵称，个性化称呼

notification_enabled:
  类型: String  # 注意：用户变量只支持String
  默认值: "true"
  用途: 是否开启提醒功能

preferred_review_time:
  类型: String
  默认值: "20:00"
  用途: 用户偏好的复盘时间
```

### 应用变量（临时使用）
```yaml
current_operation:
  类型: String
  默认值: "idle"
  用途: 当前操作状态（planning/reviewing/querying）
  注意: 每次工作流执行后重置，不要依赖它存储数据

temp_plan_text:
  类型: String
  默认值: ""
  用途: 临时存储用户输入的规划文本，准备写入数据库
```

## 四、为什么这样设计

### 1. 最少必要原则
只保留真正需要的变量，避免管理复杂度。

### 2. 变量不是存储方案
**关键认知**：变量是配置和状态管理工具，不是数据存储工具。

### 3. 数据库才是核心
- 规划内容 → 数据库
- 复盘记录 → 数据库
- 历史数据 → 数据库
- 变量只管个性化设置

## 五、实战经验总结

### 其他用户的教训

1. **记账助手案例**
   - 错误：用变量存储账目
   - 正确：变量存货币单位偏好，数据库存账目

2. **学习助手案例**
   - 错误：用应用变量存学习进度
   - 正确：数据库存进度，变量存学习风格偏好

3. **日程管理案例**
   - 错误：用用户变量存JSON格式的日程
   - 正确：数据库存日程，变量只存提醒开关

### 避坑指南

❌ **不要用变量存储业务数据**
- 早上的规划不要存在变量里
- 复盘内容不要存在变量里

✅ **变量只用于**
- 用户偏好设置
- 临时状态标记
- 系统信息获取

## 六、最终建议

### 对于你的复盘教练

1. **开场白处理**
   - 使用固定开场白
   - 在提示词中根据时间动态调整第一句问候

2. **变量精简设计**
   - 系统变量：user_id, current_date, current_time
   - 用户变量：user_name, notification_enabled
   - 应用变量：current_operation（可选）

3. **核心数据全部走数据库**
   - 不要试图用变量解决跨会话存储
   - 数据库是唯一可靠的方案

### 配置优先级
1. 先配置数据库表 ⭐⭐⭐⭐⭐
2. 再配置提示词 ⭐⭐⭐⭐⭐
3. 最后配置变量 ⭐⭐⭐
4. 开场白可以后期优化 ⭐⭐
